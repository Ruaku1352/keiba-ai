> 開発記録。最新の状況と使い方はリポジトリ直下の README を参照。

**買い方と対象は変えない。** 重賞のみ（G1 / G2 / G3 / G。障害の J.G と L は除く）・
予測上位6頭の3連単BOX（120点・12,000円）・選別なし。新しい探索はしていない。

## 仕様書で確認したこと

### 出馬表はどこから取れるか

- **データ種別 `RACE`** の RA（レース詳細）・SE（馬毎レース情報）に、データ区分
  `1:出走馬名表(木曜)` `2:出馬表(金・土曜)` として入る（レコードフォーマット「データ区分」）。
  確定成績（5/6/7）と同じレコード種別で、同じキー（開催年〜レース番号＋血統登録番号）。
- **オプション**：`1`（通常データ・差分）で届く。実際に `py -m src.jvlink fetch --option 1` で
  日曜の出馬表（区分2）24レースと月曜の1レースが届いた。
  `2`（今週データ）は「非蓄積系ソフトが今週ぶんだけ読む」用で、直近の未来のレースと直前の成績だけを読む。
  このプロジェクトは蓄積系（全期間を保存している）なので、これまでどおり `1` を使う。
- 区分1・2で**値が入らない項目**（仕様書の ○/－ の表）：
  | 項目 | 区分1（出走馬名表） | 区分2（出馬表） |
  |---|---|---|
  | 枠番・馬番 | 入らない | 入る |
  | 騎手・負担重量 | 入る | 入る |
  | 馬体重・増減 | 入らない | 入らない |
  | 天候・馬場状態 | 入らない | 入らない |
  | 出走頭数（RA） | 入らない（登録頭数のみ） | 入らない（登録頭数のみ） |
  | 着順・タイム・コーナー順位・脚質判定・オッズ | 入らない | 入らない |
- 取消・除外：SE の異常区分 1〜3（出走取消・発走除外・競走除外）が付いた馬は外す。
  乗り替わりは SE の騎手コードが新しい版で届く。**データを取り直して予測をやり直せば反映される**
  （データ区分の重複解消は確定レースと同じで、作成日が新しく確定度が高い版が残る）。
- 同じレースに速報（区分3以上）が届いていれば、そのレースは結果が出始めているので予測対象から外す。

### その他

- **前3ハロン（RA）**：「200m で割り切れない距離は、端数に 400m を足した距離のタイム」
  （= ラップの先頭3本の合計）。ラップタイムも「最初の1本目が端数の距離」。
  つまり 1700m の前3Fは 500m のタイムで、ラップの先頭3本の合計と**定義が同じ**。
  `diagnose check-3f` で実データでの一致を確認する。
- **今回レース脚質判定（SE）**：「1:逃 2:先 3:差 4:追 0:初期値」。値が入るのは区分6・7だけ
  （1〜5 と海外は初期値、地方は混在）。`0` は「未設定」なので、変換で欠損（NaN）にしている
  （v5 から。coverage の欠損率もこの NaN を数えている）。

## 判断したこと

### 1. 特徴量は「前日までに確定したレース」だけで作る（学習も予測も）

validate（v5）の特徴量は、騎手・調教師の成績に**同じ日のより前のレース**を含めていた
（as_of="race"）。実戦では前日の夜に予測するので、当日の他のレースの結果は無い。
このままだと学習と予測で特徴量の意味がずれ、「学習の経路と予測の経路で一致」もしない。

そこで `features.add_all_features(..., as_of="day")` を追加し、v6 は学習も予測もこれを使う。
同じ日の行を「過去」に含めない集計（`leakfree.*_excluding`）で、騎手・調教師・騎手×競馬場/芝ダ・
騎手直近100走・ペースの条件別標準化・想定ペースを作り直す。馬の成績は1日1走なので変わらない。

- **as_of="race"（既定）の結果は変えていない。** 変更前の出力と完全一致することを確認した
  （validate の数字はそのまま再現できる）
- 「validate と同じ特徴量・パラメータ」からの違いはこの点だけ。特徴量の列・パラメータは同じ。
  影響の大きさは `diagnose weight`（as_of=day）と validate（as_of=race）の AUC・達成率で比べられる

### 2. ラウンド数は 454（fold 5 の best iteration）

全データで学習すると early stopping に使う検証データが無い。候補は中央値 376 と fold 5 の 454。
**454 にした。** 理由：
- 学習データの量と期間が全データ（2003〜2026）に一番近いのは fold 5（2003〜2022）。
  ほかの fold は学習期間が短く、直近の傾向を含まない
- fold ごとの値（419 / 337 / 315 / 376 / 454）は学習データの量に対して単調ではないので、
  「データが増えるほど伸びる」とは言えない。中央値 376 を選ぶ理由も同じくらい弱い。
  そのため「一番近い条件の値」を採った
- 376 と 454 の差はこのデータで測っていない（全データの学習には検証データが無いため）
- `--rounds` で変えられる

### 3. 再現性

`deterministic=True`・`force_col_wise=True` を足し（乱数シードは config の `seed=42` のまま）、
同じデータなら同じモデルになるようにした（テスト `test_training_is_reproducible`）。

### 4. 予測の経路

`predict.build_prediction_features(history, targets, lap_df)`：
1. 予測対象の**結果の列をすべて消す**（着順・タイム・タイム差・上がり・オッズ・人気・コーナー順位・
   脚質判定・前後3F）。予測対象のレースIDは履歴とペース表からも除く
2. **予測対象の日ごとに**、その日より前の確定レースだけを履歴にして作る
   - 同じ日の対象レースどうしは as_of="day" で互いに除かれる（同じ騎手が2レースに乗っても、
     もう片方を過去の騎乗として数えない）
   - 日曜と月曜をまとめて予測しても、月曜のレースは日曜の対象レース（未確定）を見ない
     （最初は「全部を同じ集計日にまとめる」方式にしたが、日曜と月曜の両方に出る馬がいると
     日曜の行が「前走」になってしまうことがテストで分かったので、日ごとに作る方式にした）
3. 馬体重は「その馬の直近の確定レースの馬体重」、増減は 0（計量不能の回は飛ばす。前走が無ければ欠損）
4. 馬場状態は未発表なので**「良」と仮定**し、警告を出す。`--going 稍重` などで指定し直せる
5. 学習の経路と同じ `add_all_features` を通す

**テストで確認していること**（`tests/test_v6_predict.py`）：
- 過去のレースを学習の経路・予測の経路の両方で作ると、馬体重・増減以外の全列（合成データでは74列）が一致する
  （1日に重賞2つ・騎手が重なる合成データで、3つの日について）
- 実際の馬体重を渡せば、馬体重も含めて全列が一致する
- 予測対象の結果の列をでたらめに書き換えても、特徴量も予測確率も変わらない
- 履歴に予測対象レースの結果が紛れ込んでいても使わない
- 同じ日の重賞を1つずつ予測しても、まとめて予測しても同じ
- 日曜＋月曜をまとめて予測しても、月曜だけを予測したときと同じ
- 騎手通算騎乗数が「前日までの騎乗数」と一致する（同じ日のもう1つの対象レースを数えない）

### 5. 予測確率

LightGBM の出力（勝つ確率のスコア）を**レース内で合計1に正規化**した値。予測順位はこの順。
買い目はこの上位6頭（同点は馬番の若い方）。

### 6. 出力

- コンソール：重賞ごとに見出し（日付・競馬場・R・レース名・格付け・芝ダ距離・頭数・データの時点）、
  順位表、`買い目: 3連単 5・3・12・1・8・14 の6頭BOX 120点 12,000円`
- 枠順未確定（出走馬名表）のレースは【注意】を出し、馬番の代わりに馬名で買い目を表示する
- CSV（`data\predictions\predict_*.csv`、UTF-8 BOM 付き）の先頭7列は
  `レースID, 日付, レース名, 馬番, 馬名, 予測確率, 予測順位`。8列目以降に騎手・格付け・競馬場・距離・
  芝ダ・頭数・買い目・データ区分・データ作成日・枠順確定・馬体重の扱い・馬場状態の扱い・モデル名・
  モデル学習終了日・データ時点
- 前日までの開催で結果がまだ届いていない日があれば【注意】で知らせる
  （その日の成績は特徴量に入っていない。結果が届いたら取り直して再実行すれば反映される）

### 7. 練習モード（replay）

- 指定日の確定した重賞を、結果を消して予測の経路に通す。履歴は前日まで
- **馬場状態は実際の値を使う**（既定）。発表前の想定を試すなら `--assume-going`（良と仮定）
- 同じレースを学習の経路（`make_training_frame(until=その日)`）でも作り、
  一致しなかったセルの数を表示する（馬体重・増減を除いて 0 になるはず）
- モデルの学習終了日がその日以降なら【注意】を出す

### 8. 馬体重の代用の影響の測り方（diagnose weight）

validate と同じ5 fold で、fold ごとにモデルを1つ学習し、検証期間を
「実際の馬体重」と「代用（前走・増減0）」の2通りで予測して AUC・重賞の達成率を比べる。
馬体重から作る特徴量は「馬体重」「場体重増減」の2列だけなので（テストで確認済み）、
特徴量の表の2列を置き換えるだけで、全レースを予測の経路に通したのと同じになる。
学習は validate と同じく検証期間で early stopping（比較のため。実戦モデルは固定 454 ラウンド）。
