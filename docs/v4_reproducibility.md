# v4：再現性の検証（依頼A〜C）

> 開発記録。最新の状況と使い方はリポジトリ直下の README を参照。

**このセクションの目的は「新しい良い数字を出すこと」ではない。**
v3で160通りの条件を探索した結果、達成率10%超えの条件がいくつか出た。
しかし160通りも試せば、真に効果がなくても偶然良く見える条件は必ず出る。
v4は **v3の結論を別の期間に当てて、どれが本物かを切り分ける** ためのコード。

対応ファイル：`src/validate.py`（+ `trifecta.two_proportion_test`）

## 検証する4つの仮説

| # | 仮説 | v3での値 |
|---|---|---|
| H1 | 重賞は平場より達成率が高い | 7.362% vs 3.687% |
| H2 | G1はG2/G3より達成率が高い | 9.278% vs 6.154% / 6.950% |
| H3 | 上位6頭BOX(120点)が予算1万円台で最良 | 7.362%（下限5.365%） |
| H4 | レース選別では達成率は上がらない | 最良でも下限6.281% |

**探索は一切しない。** H4で使う条件はv3のトップ3を `FIXED_CONDITIONS` として
定数で固定してある。ここに条件を足さないこと（足せば多重比較が悪化するだけ）。

## 依頼A：時系列クロスバリデーション

| fold | 学習 | 検証 |
|---|---|---|
| 1 | 2003〜2010 | 2011〜2013 |
| 2 | 2003〜2013 | 2014〜2016 |
| 3 | 2003〜2016 | 2017〜2019 |
| 4 | 2003〜2019 | 2020〜2021.7 |

### なぜ walk-forward なのか

競馬は年々レース体系・馬場・馬の質が変わる。ランダム分割の通常のCVは
「未来を学習して過去を予測する」ことになり、実戦と条件が違う。
walk-forward なら各foldが「その時点で持っていたデータだけで学習し、次の数年を予測する」
という実戦そのものの形になる。
`test_default_folds_are_walk_forward` が全foldで学習終端 < 検証開始を検証している。

### 2つの独立性を守っている

1. **特徴量は全期間から1度だけ作る。** foldごとに作り直すと、
   序盤の馬の通算成績がリセットされて別物になる。切るのは学習・検証の窓だけ。
2. **難易度指標の分位点はfoldごとに、そのfoldの検証データだけから計算する。**
   全期間の分位点を使うとfold間で情報が共有されてしまう。
   `test_folds_do_not_share_quantiles` で担保。

## 依頼B：仮説ごとの判定

### 信頼区間の重なりではなく、差そのものを検定する

v3までは「区間が重ならないか」で有意性を見ていた。これは変更した。

**区間が重ならないことは、差があることの十分条件だが必要条件ではない。**
つまり重なりだけで判定すると、本当は差があるケースを見逃す（検出力が落ちる）。
そこで `trifecta.two_proportion_test()` を追加し、差そのものをz検定する。

差の信頼区間には **Newcombe のスコア法** を使った。個々のWilson区間から
組み立てるので、達成率が数%と0に近い状況でも下限が負に飛び出しにくい。

```python
trifecta.two_proportion_test(hits_a, n_a, hits_b, n_b)
# → {"差", "z", "p値", "差下限", "差上限", "有意"}
```

### 各仮説の判定基準

- **H1**：何fold中いくつで重賞が平場を上回ったか＋全foldプールでの検定
- **H2**：何fold中いくつでG1が最高だったか＋G1 vs G2/G3 の検定。
  G1はfoldあたり30〜60レースなのでレース数を必ず表に出す
- **H3**：F2→6→10(80点) / F3→6→8(90点) / 上位6頭BOX(120点) の3つで比較。
  達成率と下限、両方の観点で「何foldで最良だったか」を数える
- **H4**：固定3条件を各foldに適用し、基準（全重賞）より下限が上がったfold数を数える

**H4の判定で重要な点**：fold1で条件Aが良く、fold2で条件Bが良い、という状態は
「どの条件も一貫して効いていない」＝ノイズを拾っていた証拠。
全foldで下限が改善した条件だけを `全foldで下限が改善した条件` に載せる。

## 依頼C：結論の要約

`v4["recommendation"]` が、買う対象・買い方・期待達成率と信頼区間・
選別条件の要否・この戦略の限界を出力する。

判定は明示的なルールとして書き下してある（`validate.recommend`）ので、
ルールが気に入らなければ H1〜H4 の中身を見て自分で覆せる。

- 買う対象：H1が有意なら「重賞のみ」、H2も有意なら「とくにG1」を追加
- 買い方：H3で**下限**が最良だったfoldが最も多かったもの
- 選別条件：H4で全foldで一貫して効いた条件があるときだけ「使う」

## v4で追加したテスト

```bash
python -m pytest tests/ -q     # 93件（v1:11 + v2:35 + v3:24 + v4:24）
```

v4は判定コードなので、テストも**判定ロジックの正しさ**を見る。
仮説が真のデータ／偽のデータを人工的に作り、期待どおりの結論が出るか確認する：

- 重賞が明確に良いデータ → H1が「3/3で再現」「有意」「差の区間が0をまたがない」
- 差がないデータ → H1が「有意でない」（偽陽性を出さない）
- G1が突出したデータ → H2が「3/3でG1が最高」
- 指標がランダム → H4が「効いていない」と結論
- **本当に効く指標を仕込む → H4がちゃんと「効いた」と検出する**
  （検出力がないから「効かない」と言っているわけではない、という確認）
- 比率検定が手計算と一致し、同率ならz=0・p=1になる
- 条件の指標列が欠けていたら空を返す（誤って全件を買わない）

合成データの「熱い当たり」はサンプリングではなく決め打ちで作っている。
乱数だと「差がないはずなのに偶然有意」が5%の確率で起きてテストが不安定になるため。
