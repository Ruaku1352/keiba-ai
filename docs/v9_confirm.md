# v9：重賞で1回だけの確認のテスト（`py -m src.v9 confirm`）と、有馬記念当日の仕組みの実装計画

> 開発記録。確認のテストは、結果を見てから条件を変えないために、内容と判定のルールを先に固定した（依頼書 v9 のとおり）。

## 1. 確認のテスト（固定した内容）

| 案 | 買い方 | 確率 | 3連単などの確率 | 金額・点数 |
|---|---|---|---|---|
| F | 券種混合（3連単・3連複・馬単・馬連） | 市場（単勝の確定オッズ）＋当日の傾向（3b。同じ日・同じ競馬場・同じ芝ダで、発走の40分以上前に発走したレース）。係数はその fold より前の fold の平場で | Henery 型。γ・δ は市場の確率について前の fold の平場で | 推定配当 × 金額 ≥ 50,000円 × 1.4、15点まで、12,000円 |
| F2 | F と同じ | ∝ exp(0.5·log モデル + 0.5·log 市場)（レース内で正規化）。モデルは B と同じ今のモデル。3b は入れない | Henery 型。γ・δ はこの確率について前の fold の平場で | F と同じ |
| B | 今のモデルの上位6頭の3連単BOX | 今のモデル（本番と同じ特徴量。v8 の baseline と同じ fold の予測） | — | 120点 × 100円 = 12,000円 |

- F・F2 の配当の推定はどちらも市場の確率と払戻率から（v8 と同じ）。重賞の確定オッズ（取り直した分）は使わない
- 対象：重賞（G1 / G2 / G3 / G。障害の J.G とリステッド L は除く）、fold 2〜5 の検証期間のうち 2026-10-25 まで
- 当日の傾向に使えるレースが無い重賞も除外しない（傾向の項は 0）

### 判定（主指標）

- 1レースごとに「払戻の合計 ≥ 50,000円」（熱い当たり）
- 同じレース同士の対応のある比較で、F − B と F2 − B の差の **97.5% 区間**（Newcombe 法10。p値は正確な McNemar）
- 下限が 0 を超えた案を合格。**両方合格なら達成率の高いほう、片方だけならその案、どちらも合格しなければ B のまま**
- 参考（判定には使わない）：F − F2、達成率（Wilson 95%）・的中率・回収率・平均点数・平均投資、F・F2 の予測の達成確率と実際の差、
  グレード別、fold ごと、熱い当たりの払戻の分布（件数・中央値・四分位・最大）

### 実装で判断したこと

- **重賞でこの3つ以外の案は計算しない**。v9 は v8 とは別の入口（`src/v9.py`）にし、F・F2・B だけを評価する。
  v8 の平場用のガード（`exploration_only`）はそのまま残している
  （F の確率を作るときに、保存済みの傾きの表を使う。表には他の案の確率の列もあるが、重賞では読まない）
- **同じレースで比べる**：どれか1つでも作れないレース（払戻が無い、単勝オッズが欠けている、1着が同着で 3b の確率を作れない、など）は
  3つとも外し、外したレースの数と理由を出力と `skipped.csv` に出す
- B の上位6頭は今のモデルの確率（prob）の順。v8 の baseline と同じ fold の予測（保存済みの `oof_base.pkl`）
- F2 の γ・δ：1つ目の fold（fold 2 の推定に使う fold 1）も含めて、同じ F2 の式（モデル 0.5・市場 0.5）で推定
- 買い目の候補の上位10頭は、F は F の確率、F2 は F2 の確率の順
- **やり直しの扱い**：結果は毎回 `data\v9\confirm_<日時>\` に別に保存し、前の結果は消さない。2回目以降は
  `--rerun-reason "直したこと"` が無いと実行しない。`data\v9\confirm_runs.csv` に実行ごとの日時・判定・理由が残る

### 実行の順番

| 順 | コマンド | 期待される出力 | 時間の目安 |
|---|---|---|---|
| 1 | `py -m src.v9 confirm` | 最初に区切り線の中に「■ 判定：F を採用 / F2 を採用 / B のまま」と F − B・F2 − B の差・97.5% 区間・p値・合格/不合格、重賞のレース数・期間・外したレースの数、ルールの文。そのあと参考の表（F − F2、達成率、グレード別、fold ごと、払戻の分布、外したレースの理由）。最後に保存先と判定の再掲 | 5〜15分（保存済みの fold の予測・傾きの表を読む。重賞は約1,500〜1,800レース） |

保存済みの表が無い・作り直しになる場合（v8 の rating のあとに oof_base を作り直した場合など）は、傾きの表の作成で +15〜25分。

## 2. 有馬記念当日の仕組み（v8 の設計 4）の実装計画と見積もり

設計は `docs/v8_raceday_design.md`。確認のテストの判定で F か F2 を採用した場合の計画（B のままなら、今の週末の流れ＝前夜の予測で6頭BOX）。

### 共通（F・F2 どちらでも）

| 作業 | 中身 | 規模 |
|---|---|---|
| 前の晩の準備 `py -m src.raceday prep --date 20261227` | 出馬表（区分1/2）から対象レースの出走馬・馬番を保存。γ・δ（と F なら 3b の係数）を、その日より前の平場の全期間で推定して保存（検証と同じ「前の期間の平場で」）。馬場 4通り（良・稍重・重・不良）の今のモデルの予測（F2 で使う。F でも B の参考に表示） | 小〜中 |
| 速報オッズ | 既存の `rt-odds`（0B30＝全券種）を使う。単勝だけなら 0B31。取得時刻と発表時刻を保存 | 小（実装済みのものを流用） |
| 買い目の計算 | 単勝の速報オッズ → 市場の確率 → （F：3b の傾き / F2：モデルと 0.5・0.5）→ Henery 型 → 券種混合（余裕×1.4・15点まで・12,000円） | 小（検証のコードをそのまま使う） |
| 本物のオッズでの確かめ | 選んだ買い目を当日の速報オッズ（0B30）で見て、`オッズ × 金額 < 50,000円` の買い目に警告。届く金額（`ceil(50,000 ÷ オッズ ÷ 100) × 100`）と、足すのに要る額を表示。合計が予算を超える場合はその旨も | 小 |
| シート | 「当日」シートに、スマッピーにそのまま入力できる形（券種・組番・金額）で上から並べる。熱さの一覧は参考として小さく。予測の達成確率・最終更新時刻・使ったレース・使ったオッズの発表時刻。予測の達成確率が 6% 未満なら「例外を考えてもいい場面」 | 小〜中 |
| 時刻の制御 | 発走 60分前に仮の買い目（別の欄に残す）、20分前に最終（以降は更新しない）。タスクスケジューラで 10分おきに `py -m src.raceday update` | 小 |
| 練習 | 12月の G1 の日に本番と同じ流れで動かし、速報の遅れ・処理時間・オッズのずれ（odds-drift）を測る | あなたの実行 2〜3回 |

### F の場合（当日の傾向が要る）

| 作業 | 中身 | 規模 |
|---|---|---|
| その日の結果の取り込み | 0B12（速報成績）で、その日の先に終わったレースの着順・4角の位置・馬番を読む（3b の項に要るもの） | 中（偽物の JV-Link でテスト） |
| 当日の傾向 | 最終更新の時点で実際に届いていたレースのうち、対象レースの発走の 40分以上前に発走したもの（同じ競馬場・同じ芝ダ）から 3b の項 | 小（検証と同じ関数） |
| 自動の切り替え | その日の結果が1レースも取れない・取り込みが失敗したときは「市場だけ」（傾きの項 0）に自動で切り替え、シートに「当日の傾向なし（市場だけ）」と表示 | 小 |

**見積もり（F）**：こちらの実装 3〜4回のやり取り（テスト込み）＋ 練習 2〜3回。

### F2 の場合（当日の傾向は要らない）

- 前の晩のモデルの予測（馬場 4通り。当日の発表の馬場を選ぶ）と、当日の単勝の速報オッズだけで計算できる
- 0B12 の取り込み・当日の傾向・自動の切り替えが要らない分、小さい
- 取消があれば、その馬を除いてモデルの確率と市場の確率をそれぞれ正規化し直してから混ぜる

**見積もり（F2）**：こちらの実装 2〜3回のやり取り（テスト込み）＋ 練習 1〜2回。

### 順番（どちらの場合も）

1. 前の晩の準備と、当日の計算（過去の重賞の日のデータで「当日だったら」を再現するテスト付き）
2. 本物のオッズでの確かめとシートの表示
3. タスクスケジューラと時刻の制御
4. 12月の G1 で練習（速報の遅れ・処理時間・オッズのずれを記録）→ 直す → 12月中旬に固定
