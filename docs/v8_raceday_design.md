# v8 4：有馬記念当日の運用の設計（設計と見積もりだけ。実装は検証の結果を見てから）

> 開発記録。会場には PC を持っていかない。家の PC をつけたままにしてタスクスケジューラで自動で動かし、
> 会場ではスマホでスプレッドシートを見るだけにする。

## 全体の流れ

```
前の晩（土曜 12:00 の出馬表の後）           当日（タスクスケジューラで 10〜15分おき）
──────────────────────────────          ──────────────────────────────────────
fetch --option 1（出馬表・確定成績）         ① 速報の取り込み（0B12 結果 / 0B31・0B36 オッズ / 0B14 取消・馬場）
predict（全履歴から特徴量。約2分）           ② 当日の傾向の更新（その日の先に終わったレースだけ）
  └ 馬場 4通り（良・稍重・重・不良）を保存      ③ 2段目（オッズと混ぜる）→ 3連単の確率 → 買い目
  └ 「当日に変わらない部分」を保存（下）        ④ シートへ書き込み（最終更新時刻・使ったレース・オッズ時刻）
シートに「前夜の予測」を書く                    ⑤ 記録（各レースの発走時刻・結果/オッズが取れた時刻）
```

## 時刻のきまり（設定で変えられるようにする）

| 名前 | 既定 | 意味 |
|---|---|---|
| `final_before` | 20分 | 対象レースの発走のこの分前で**最終更新**。それ以降は更新しない（買い目が変わらない） |
| `provisional_before` | 60分 | この分前の時点の買い目を「**仮の買い目**」として別の欄に残す（最終更新が失敗したとき・早く買いたいとき用） |
| `result_delay` | 20分 | 結果が届くまでの遅れの見込み。当日の傾向に使えるのは 発走 ≤ 対象の発走 − (final_before + result_delay) のレース |
| `interval` | 10分 | 当日の更新の間隔（タスクスケジューラ） |

- 当日の傾向は「最終更新の時点で**実際に届いていた**レースだけ」で計算する。見込み（20分）より遅れて届かなかったレースは使わない
  （検証の「発走の40分前までに発走したレース」は上限で、本番はそれ以下になる）
- 最終更新の処理が `final_before` を過ぎても終わらなければ、書き込まずに終了し、直前の更新（または仮の買い目）が残る

## 1分以内にするための分け方

今の predict が約2分かかるのは、**生データ（RA/SE/HR の CSV）を全部読み、全期間の特徴量を作り直している**ため
（合成データで測ると、変換と特徴量でほぼ全部。モデルの予測そのものは1秒未満）。

当日に変わるのは次のものだけ：
- その日の先に終わったレースの結果（当日の傾向）
- オッズ（2段目・配当の推定）
- 取消・騎手変更・馬場（取消は出走頭数、馬場は 4通りから選ぶだけ）

なので、前の晩に次を `data\raceday\<日付>\` に保存しておく：
1. 対象レースの全頭の**当日に変わらない特徴量**（馬場 4通り × 全頭。予測の経路で作ったもの）
2. 1段目のモデルの予測（馬場 4通り）
3. 2段目の係数、γ・δ、当日の傾向の計算に要る過去の基準（後3F の条件ごとの平均・標準偏差）

当日の処理（見積もり）：
| 処理 | 中身 | 時間の見積もり |
|---|---|---|
| 速報の取り込み | JVRTOpen 0B12（その日の結果、開催日単位）・0B31（対象レースの単勝オッズ）・0B36（3連単オッズ）・0B14（取消・馬場） | 各 1〜5秒（未計測。練習で測る） |
| 当日の傾向 | その日の数十レースから集計するだけ | 1秒未満 |
| 1段目の予測 | 前夜の 4通りから馬場を選び、当日の傾向の列だけ差し替えて予測 | 1秒未満 |
| 2段目・3連単の確率・買い目 | 1レース分 | 1秒未満 |
| シートへの書き込み | gspread（1〜2回の API 呼び出し） | 2〜5秒 |
| 合計 | | **10〜30秒**（主に速報と API の待ち時間） |

※ 当日の傾向を本番で使うかは検証（3）の結果しだい。使わないなら 1段目は前夜のまま（馬場だけ選ぶ）で、さらに速い。
※ 取消があったときは、その馬を除いてレース内の確率を正規化し直す（特徴量の「出走頭数」などは前夜のまま。差は小さい）。

## シートの表示（「当日」シートを1枚足す想定）

```
有馬記念（2026-12-27 中山11R 15:40）  最終更新 15:20:05  ［確定］
使ったレース: 中山 1R〜8R（芝 4レース）  使ったオッズ: 15:18 発表  馬場: 良（発表）
仮の買い目（14:40 時点）: …（同じ形）

カード1  3連単フォーメーション   1着 [ 5 ]   2着 [ 3 ・ 12 ]   3着 [ 1 ・ 3 ・ 8 ・ 12 ・ 14 ]   6点 × 200円 = 1,200円
カード2  3連複 …
合計  カード 3枚  12,000円   予測の達成確率 9.1%
```

- 券売機のマークカード（3連単フォーメーション）に**そのまま塗れる形**で、1着・2着・3着の欄ごとに馬番を並べる。カードの枚数と金額も
- 失敗したら：前の晩の予測と、その時点までの最後の更新がそのまま残る（シートは上書きだけで、消さない）

## 速報の遅れの記録（練習で実測する）

`data\raceday\timing.csv` に1行ずつ追記する：

| 列 | 中身 |
|---|---|
| 記録時刻 | 更新を始めた時刻 |
| レースID・発走時刻 | 0B12 に出てきたレース |
| 結果を初めて取れた時刻 | そのレースの 0B12 のレコード（区分 3 以上）を最初に読めた更新の時刻 |
| 結果の区分 | 3（3着まで）/ 5（全馬）/ 6（コーナー通過順まで） |
| オッズの発表時刻 | 0B31・0B36 のレコードの「発表月日時分」 |
| 処理時間 | ①〜④ それぞれの秒数 |

11月下旬〜12月上旬の G1（2〜3回）で、本番と同じ流れ（前夜 → 当日 10分おき → 最終 20分前）を動かし、
「発走から結果が取れるまでの分」の分布と、処理時間を測る。その結果で `result_delay` と `interval` を決める。
あわせて時系列オッズ（0B41・0B42。1年保存）を取っておけば、「締切20分前のオッズと確定オッズの差」も測れる。

## タスクスケジューラ

- 当日 9:30〜（対象レースの発走 − 20分）まで 10分おきに `py -m src.raceday update`（仮の名前）
- 発走 − 60分 の回で仮の買い目を保存、発走 − 20分 の回で最終更新して以降は何もしない
- PC のスリープ・Windows Update の再起動を止めておく（電源設定・アクティブ時間）。JV-Link の利用キーの有効期限も前日に確認

## 追加：当日の傾向を「参考情報」としてシートに出す（検証の結果に関係なく）

買い目の計算に使うかどうかとは別に、当日の馬場の様子を数字で見られるようにする。
会場でパドックや返し馬を見るときの参考で、買い目は自動では変えない。

### 表示する内容（「当日」シートの下に、芝・ダート別に）

```
［参考］当日の傾向  中山 芝（使ったレース: 3R・5R・6R・8R、15:00 時点）   ※ 判断材料の1つ。買い目には入っていない
  内枠（馬番の前半）の3着内率   58%（7/12）   ← 全体の平均 50%
  3着内の馬の4角の位置        前から 28%   ← 0%=先頭, 50%=中団, 100%=最後方。小さいほど前残り
  上がりの速さ                 +0.6σ        ← 同じ場・距離の過去より速い（差しが届きやすい）
  1着馬の脚質                  逃げ 1 / 先行 2 / 差し 1 / 追込 0
  開催の傾向（前日まで、同じ芝・距離帯）  内 +0.04 / 前残り +0.02 / 開催 4日目

  有馬記念の出走馬との組み合わせ（上位6頭）:
    5番 内枠・先行   → 当日の傾向に合う
    12番 外枠・差し  → 当日の傾向に合わない
```

- 数字の元は検証の 3（当日の傾向）・3c（開催の傾向）と同じ計算（`trackbias.race_bias_stats` / `tilt.add_meeting_features`）。
  使ったレースの一覧と件数を必ず一緒に出す（3レースで 7/12 のように、件数が少ないと偶然の幅が大きいため）
- 「内枠の3着内率」は分かりやすさのため、3着以内の馬のうち馬番が前半（内）だった割合で出す（検証の特徴量は平均位置の差）
- 傾向に合う・合わないは、内枠傾向 × 馬番位置、前残り傾向 × 脚質スコア の符号で判定する（3b の項と同じ）
- 当日の結果は速報系 0B12 で取る（当日の更新①と同じ取り込み）。前の晩は「開催の傾向」だけを出す
