## 1.5 格・着差・推移・タイム指数（`src/levels.py`）

レースの格：0 新馬・未出走 / 1 未勝利 / 2 1勝（500万下）/ 3 2勝（1000万下）/ 4 3勝（1600万下）/ 5 OP / 6 L / 7 G3・格なし重賞 / 8 G2 / 9 G1。
競走条件コードは年齢ごとに5つある（夏の「3歳以上」で 3歳は500万下・4歳以上は1000万下、という時代があった）ので、
**5つのうち一番上の格**をそのレースの格にした。古い「400万下」「900万下」などは収得賞金の上限で 1勝/2勝/3勝 相当にまとめた。

| 特徴量 | 中身 |
|---|---|
| 今回の格 / 前走の格 / 過去5走平均格 / 過去最高格 | |
| 格の差_前走 / 格の差_過去最高 | 今回 − 前走、今回 − 過去最高（＋なら昇級） |
| 同格以上_最高着順 / 同格以上_平均相対着順 / 同格以上_出走数 | 今回の格以上だった過去のレースだけで（格上で善戦しているか） |
| 前走タイム差 / 過去5走平均タイム差 | 勝ち馬とのタイム差（1着は2着との差がマイナス） |
| 相対着順の傾き_5走 | 直近5走の相対着順（0=1着）の傾き。マイナスなら良くなっている |
| 直近3走と通算の差_相対着順 | |
| タイム指数_前走 / 過去5走平均 / 最高 | 走破タイムを 同じ競馬場・距離・芝ダ・馬場 の過去（前日まで）の平均・標準偏差で標準化（速いほど大） |

すべて「前の行だけ」から作る。テストで、そのレースの着順・タイム差・タイムを書き換えても、そのレースの特徴量が変わらないことを確認した。

## 2b〜2e（`src/market.py`・`src/bets.py`）

- **2b**：1段目は out-of-fold の予測（既定は 1.5 を足したモデル。`--stage1 base` で今のモデル）。
  2段目の係数は、その fold より前の fold の平場だけで推定する（fold 1 は推定に使う期間が無いので、比べるのは fold 2〜5）。
  「オッズも特徴量に入れた1つのモデル」は、市場確率の log を特徴量に足して同じ fold で学習したもの
- **2c**：Harville と Henery 型（2着・3着を p^γ・p^δ で計算し直す。Lo & Bacon-Shone と同じ形）。γ・δ も walk-forward
- **2d**：市場の確率から3連単・3連複・馬単・馬連の組の確率を出し、推定配当 = 100 × 払戻率 ÷ 組の確率。
  払戻率は 3連単 72.5% / 3連複・馬単 75% / 馬連 77.5%（現在の値。2014年6月より前は違った可能性があるので、年ごとの比も出す）
- **2e**：買い方 S0〜S5（`py -m src.v8 bets` の表を参照）。配当は 2d の推定で選び、評価は実際の払戻（同着はすべての的中組）
  - S3 のフォーメーション：1着・2着・3着の欄に「確率の上位 a・b・c 頭」を塗るカードを最大3枚（a≤3, b≤6, c≤10）
  - S4 の券種混合：1点ごとに「それ1点で基準に届く金額」を付け、確率÷金額の大きい順に予算まで（貪欲法）。
    最適解ではない（組み合わせの払戻の足し算は使っていない）。予測の達成確率は、選んだ全部の推定払戻の合計で計算する
  - S4c の上限：1枚のマークカードに 4 組、券種ごとに 2 枚まで（= 8点）と**仮定**した。実際の券売機のカードに合わせて
    `bets.MARKS_PER_CARD`・`bets.MAX_CARDS_PER_KIND` を変えられる
- **確定オッズと締切前のオッズの差**：検証では確定オッズ（市場の最終的な評価）を使うが、本番では締切の少し前のオッズで買う。
  締切直前に入る大口の票で人気馬のオッズが下がり、人気薄が上がることが多いと言われる。影響は2つ：
  (1) 市場の確率が少しずれる → 2段目の混ぜ方は確定オッズで学んでいるので、締切前のオッズでは市場をやや過大・過小に見る
  (2) 推定配当がずれる → 熱い組の選び方（基準を超えるか）が境目で変わる。
  検証で効果があった案でも、本番では少し割り引いて考えるべき。時系列オッズ（0B41・0B42、1年保存）を練習のG1で取っておけば、
  「締切20分前と確定の差」を実測できる（4 の設計に入れた）

## 3 当日の馬場の傾向（`src/trackbias.py`）

- 使えるレース：同じ日・同じ競馬場・同じ芝ダで、**発走時刻 ≤ 対象の発走時刻 −（打ち切り 20分 ＋ 遅れ 20分）** のもの。
  20分・20分は `trackbias.add_track_bias_features(cutoff_min=, delay_min=)` の引数で変えられる
  （検証では `experiment.VARIANTS` の trackbias40 = 20+20 と trackbias80 = 打ち切り60+遅れ20 を並べて出す）
- 先に終わったレースが少ないとき：傾向は「合計 ÷ (レース数 + 1)」で 0 に寄せる。1R などは 0 で、「当日_使えたレース数」= 0
- テスト：対象レース自身・後のレース・別の競馬場の結果を書き換えても値が変わらないこと、境目（ちょうど40分前に発走したレース）は使い、それより後に発走したレースは使わないこと、
  使えるレースを書き換えると値が変わること
- 評価は平場の 7R 以降（後半）
- 本番で使うには、当日の結果を速報系 0B12 で取り込む必要がある（v7 の docs に作業を書いた。まだ実装していない）

## 修正：trifecta が落ちた件・γ・δ の推定が遅かった件（v8 の2回目）

- **落ちた原因**：2b の表の `attrs` に1段目の表（DataFrame）を入れていた。fold をまたいで表をつなぐとき
  （`pd.concat`）、pandas が attrs を `==` で比べ、DataFrame どうしの比較で `ValueError` になった。
  attrs には入れず、`MarketTables` の項目として渡すようにした。ほかのコマンドの attrs は数値だけ（件数・p値など）で問題ない
- **テストで見逃した理由**：合成データの fold が2つで、混ぜた確率が1つの fold にしか無く、つなぐ処理が実際には走っていなかった。
  テストを3 fold にし（混ぜた確率が2つの fold にまたがる）、**全コマンドを表の組み立て・表示・保存まで通す**ようにした。
  修正前のコードで、このテストの条件で同じ `ValueError` が出ることを確認した。
  同じテストで、bets の「熱さの一覧」の集計でも落ちることが見つかり、直した
- **γ・δ の推定が遅かった原因**：レースを1つずつ Python で回し、fold ごとに推定し直していた（実データで約40分）。
  同じ頭数のレースをまとめて行列で計算し、レースごとの対数尤度を1回だけ計算して fold ごとには足すだけにした。
  1レースずつの計算と同じ結果になることをテストで確認（合成の2万レースで約1秒）。3連単のキャリブレーションも同じ方法にした
- **保存して使い回す**：γ・δ・2c の表・2d の照合は `data\v8\trifecta_<1段目>.pkl` に保存し、
  同じ条件（fold の予測のファイルが変わっていない）なら読み直すだけにした。bets もこの γ・δ を使う。作り直すには `--refresh`
- **bets の高速化**：券種混合の貪欲法で、毎回すべての候補を計算し直していたのを、新しく押さえた並びの分だけ差し引く形にした
  （約15倍速い）。素直な版と同じ選び方になることをテストで確認（増え方がまったく同じ候補が並んだときだけ、
  どちらを選ぶかが丸めで変わることがあるが、予測の達成確率・金額は同じ）

## 追加：2e の「当たる確率」の出し方を変えて並べる

配当はどれも市場の確率（オッズ）から推定し、「当たる確率」だけを変える：

| 確率 | 中身 |
|---|---|
| モデルだけ | 1段目（既定は 1.5 を足したモデル。オッズなし） |
| 市場だけ | 単勝オッズから出した市場の勝率 |
| 混ぜたもの（2b の推定） | 2b の2段目（1着の log-loss を最小にする割合） |
| 混ぜたもの（モデル 0.25 / 0.50 / 0.75） | P ∝ exp(w·log モデル + (1−w)·log 市場)、w を固定 |

- 2b の割合は1着の log-loss に最適な値で、「払戻 5万円以上の確率」に最適とは限らないため（依頼者の判断）。
  「モデルの価値は市場からのずれにある」という仮説を、確率を市場に寄せたときに平場で達成率が下がるかで確かめる
- 2b の推定は α（モデル）と β（市場）が別々で、合計が 1 とは限らない。表の上に「モデルの割合 α/(α+β)」も出す
- γ・δ は確率の出し方ごとに、同じ walk-forward で推定する
- 熱さの一覧は時間の都合で「混ぜたもの（2b）」と「モデルだけ」の2つだけ
- **試した案の数**：bets だけで 確率6通り × 買い方6通り = **36**（コマンドの最後に一覧を出す）。
  v8 のこのフェーズの合計は 1.5：1、2b：2、2c：2、2e：36、3：2 の **43**
- 既定のレース数を1万から5,000にした（計算が6倍になったため）。`--sample 0` で全部

## 追加：3b・3c 市場の確率に傾向で傾きをつける（`py -m src.v8 tilt`、`src/tilt.py`）

最終的に使う確率は市場（＋Henery 型）なので、「市場がその傾向を織り込み切れているか」を確かめる。

    P_i ∝ exp(β·log 市場_i + Σ θ_k·項_ik)

係数はその fold より前の fold の**平場**で推定（walk-forward。比べるのは fold 2〜5）。θ が 0 に近ければ市場は織り込み済み。

| 案 | 項 | 当日の取り込み |
|---|---|---|
| 3b 当日の傾向 | 当日_内枠×枠位置、当日_前残り×脚質（発走40分前までに発走した、同じ日・競馬場・芝ダのレース。3 と同じ計算） | 要る（0B12） |
| 3c 開催の進み具合 | 開催（年・競馬場・回）の中で、同じ芝ダ・距離帯（〜1400/〜1800/それより長い）の**前日までの**内枠傾向・前残り傾向 × 枠位置・脚質、開催日目 × 枠位置 | 要らない（前日までで計算できる） |

- 比べるもの：平場の log-loss・AUC・キャリブレーション誤差、キャリブレーションの表（全レース）、
  2e の S4c（券種混合・点数の上限）を「市場だけ」と「傾けた確率」で（配当はどれも市場から推定）
- γ・δ は市場のものを使う（傾きは市場の小さな補正なので）
- 3c の開催の傾向は「合計 ÷ (レース数 + 2)」で 0 に寄せる。開催の初日は 0
- テスト：3c はその日・それより後の結果を書き換えても値が変わらない（前の日を書き換えると変わる）、開催の初日は 0。
  係数の推定が、作った正解（θ=2）を取り戻せること
- 係数の推定（条件付きロジット）で、全部 0 の列があると行列が特異になって推定が止まり、係数が 0 のまま返る不具合があったので直した
  （最小二乗で解く）。2b の推定（モデルと市場の2列）はこの状況にならないので、これまでの結果には影響しない
- **試した案の数**：2（3b・3c）。v8 のこのフェーズの合計は **45**（1.5：1、2b：2、2c：2、2e：36、3：2、3b・3c：2）

| 順 | コマンド | 時間の目安 |
|---|---|---|
| 9 | `py -m src.v8 tilt` | 10〜20分（base の保存を使う。傾向の項の作成と S4c の計算） |

運用の設計（`docs/v8_raceday_design.md`）に、当日の傾向をシートに「参考情報」として出す案を足した。

## v8b：3b+3c、金額の余裕、スマッピーの点数、本物のオッズ

### 1. 3b と 3c を一緒に入れた傾き（`py -m src.v8 tilt`）

- `P ∝ exp(β·log 市場 + θ·当日の項 + θ'·開催の項)`。推定はこれまでと同じく前の fold の平場
- 市場だけ・3b・3c・3b+3c の log-loss・AUC・キャリブレーション誤差と S4c の達成率を並べる
- **S4c の達成率の差の対応のある比較**（同じレースで、片方だけ熱い当たりになったレースの数・Newcombe の差の区間・McNemar の p 値）を
  3b − 市場、3c − 市場、3b+3c − 市場 で出す（`tilt_s4c_paired.csv`）
- 傾向の項を作るのに数分かかるので、傾きの表は `data\v8\tilt_tables.pkl` に保存して、tilt の2回目と stakes で使い回す

### 2・3. 金額の余裕とスマッピーの点数（`py -m src.v8 stakes`）

- 確率は tilt の S4c で達成率が一番良かったもの（`--source tilt3bc` などで指定もできる）
- **金額の余裕**：1点の金額を「推定配当 × 金額 ≥ 50,000円 × 余裕」にする（余裕 1.0 / 1.2 / 1.4）。
  達成の判定は予測・実際とも 50,000円のまま。余裕を上げると1点が高くなり、予算内で押さえられる並びは減る
- **スマッピーの点数の上限**：入力する点数の合計（券種は問わない）を 10 / 15 / 20 点まで、と上限なし。
  券種ごとのカードの枚数の制約（S4c）は使わない
- 表に「予測の達成確率（平均）」と「予測 − 実際」を出す。余裕で差がどれだけ縮むかを見る
- 対応のある比較の基準は「余裕×1.0・上限なし」
- **予測の達成確率の計算を直した**：これまで券種混合の予測の達成確率は、確率の上位10頭の並びの中だけで数えていた。
  馬単・3連複などは残りの着に上位10頭以外が来ても当たるので、少し小さく出ていた（全頭の並びで数えるようにした）。
  前回の「S4 × 市場 の予測 17.9%」は、直した計算では少し大きくなる＝実際（9.6%）との差は前回の表示より大きい
- **試した案の数**：tilt で 1（3b+3c）、stakes で 3 × 4 = 12。v8 のこのフェーズの合計は **58**

### 4. 本物のオッズ

#### (a) これからの分：`py -m src.jvlink fetch-odds`

- いつもの `fetch`（RA/SE/HR）は**変えていない**。オッズは別のコマンドで取る（月曜の fetch のあとに実行）
- 中身：蓄積系 RACE をもう一度開き、オッズのファイル（O1・O2・O4・O5・O6。ワイド O3 は既定では取らない）だけを読む。
  それ以外のファイルは先頭の1件で JVSkip。fetch で JV-Link がダウンロード済みのファイルを読み直すだけなので、ダウンロードはほぼ無い
- 前回の続き：初回は前回の fetch の開始時刻から、2回目以降は前回の fetch-odds の最新ファイル時刻から（state.json の "ODDS"）。
  中断しても同じコマンドで続きから
- 保存するのは確定オッズ（データ区分 4・5）だけ。`data\jvlink\odds\O6_opt1_<日時>.npz` のように、取得1回・種別ごとに1ファイル
  （圧縮した numpy。parquet などの追加のライブラリは要らない）。組が無い行は保存しない
- 容量：3連単は1レース実際の組が数千（16頭で 3,360）、圧縮後 1レース 約15KB。1週間（約290レース）で全種別合わせて 5〜10MB、1年で 0.3〜0.5GB
- 時間：JVGets はバッファの大きさに比例して遅くなる（開発者の bench：約 34ms ＋ 0.53ms/KB）。ファイルの1件目だけ大きいバッファ（83KB）で読み、
  2件目以降はその種別の大きさに合わせる。1週間のオッズのレコードは約 290 × 5 = 1,450 件、3連単（約78ms）とそれ以外（約35〜41ms）で **約1.5分**
  ＋ オッズ以外のファイルの1件目（数十〜百ファイル × 約78ms）
- 読み方の正しさ：仕様書の位置で直接読む（numpy）。SDK の構造体で読んだ結果と、O1・O2・O4・O5・O6 で一致することをテストで確認（SDK がある環境）
- `py -m src.jvlink odds-summary` で保存した件数・容量を確認

#### (b) 過去の分（2011年以降）

1. `py -m src.v8 odds-targets` … 取り直すレースの一覧 `data\v8\odds_targets.csv`
   （2011年以降の重賞すべて 約2,100 ＋ 平場の検証用 5,000。平場は fold 2 以降から乱数の種を固定して選ぶ）
2. `py -m src.jvlink fetch-odds --from 20110101000000 --option 4 --types O2,O4,O5,O6 --targets data\v8\odds_targets.csv`
   （セットアップのデータ。初回だけダイアログが出る）

見積もり：
- 読む量：JV-Link は1件ずつ順に読むので、**保存するレースを絞っても読む量は減らない**（読んだうえで対象外は捨てる）。
  2011〜2026年のレースは約 54,500。単勝（O1）は SE の確定オッズがあるので取らず、ワイドも使わないので、O2・O4・O5・O6 の4種類
- 時間：1レースあたり O2 約35ms ＋ O4 約36ms ＋ O5 約41ms ＋ O6 約78ms ≒ 0.19秒 → **約3時間**（読み込み）。
  ほかに、セットアップのデータがパソコンに残っていなければダウンロードの時間がかかる（3連単だけで 83KB × 54,500 ≒ 4.5GB。回線しだいで数時間）。
  JV-Link はダウンロードしたファイルを保存パスに残すので、以前のセットアップのファイルが残っていればダウンロードはほぼ無い
- 中断しても同じコマンドで続きから（読み終えたファイルの記録 `progress_RACE_ODDS_*`）
- 容量：絞った 約7,100 レースで **約100MB**（全レースなら約0.8GB）
- 取り直したら、最終案を本物のオッズで評価し直す（推定配当の代わりに、その組の確定オッズ × 金額で払戻を見積もり、買い目を選ぶ）。
  その評価のコードは、最終案が決まってから作る

#### (c) 当日の速報オッズ：`py -m src.jvlink rt-odds --date 20261101`

- その日の重賞（RA.csv の出馬表から。`--all` で全レース、`--race 11` で1レース）について、`JVRTOpen("0B30", "YYYYMMDDJJKKHHRR")` で

## v8c：馬のレーティング（能力が時間とともに変わる）を市場の確率への傾きに（`py -m src.v8 rating`、`src/ratings.py`）

仮説：「最近急に強くなってきた馬を、市場が評価し切れていない」。平場だけで確かめる（重賞の成績は出さない）。

### 判断したこと

- **方式：Weng & Lin (2011) の逐次ベイズ近似による Plackett-Luce**（OpenSkill の PlackettLuce と同じ式）。
  各馬の強さを N(μ, σ²) で持ち、全頭の着順を見るたびに閉じた式で更新する
  - TrueSkill は多頭数だと因子グラフの反復計算が要り遅い。多頭数版の Elo は全ペアの1対1に分ける近似で、18頭なら153組を独立に扱ってしまう。
    Plackett-Luce は「1着が残りから選ばれ、2着が残りから選ばれ…」という着順のモデルそのもので、σ で「出走数が少ない馬ほど不確か」が自然に出る
  - 強い相手（μ が高い馬）に先着すると大きく上がる（テストで確認）ので、レースの格は手で定義していない
- **能力の変化**：前走からの日数に応じて σ² を増やす（σ² += τ² × 日数/30、上限 σ0²）。休み明けほど次のレースで大きく動く
- **着差（タイム差）は使わず、着順だけ**。着差の大きさは距離・ペース・馬場で意味が変わり、補正の設定を選ぶこと自体が試行を増やすため
- **設定は決め打ち**（μ0=25, σ0=25/3, β=σ0/2, τ=σ0/50（30日あたり）, κ=1e-4。TrueSkill・OpenSkill の既定に近い値）。調整していない
- 同着は馬番順で切る。取消・中止など着順の無い行は使わない（`preprocess.basic_clean`）
- **リーク対策（as_of=day）**：日付ごとに、その日の全レースのレース前のレーティングを先に記録してから、その日の結果で更新する。
  `tests/test_v8_ratings.py`：D 日以降の着順を逆にしても D 日の値は変わらない／前日の着順を変えると変わる／同じ日の前のレースの結果は使わない
- **計算時間**：1986年からの約14万レースで、レーティング自体は 1 レース約 0.1 ミリ秒（この環境）→ 約15秒〜1分。
  データの読み込み・3b の項の作成を含めて初回 10〜20分（`data/v8/ratings.pkl`・`tilt_tables.pkl` に保存して使い回す）

### 傾きの項（3b と同じ形：P ∝ exp(β·log 市場 + θ·項)。係数はその fold より前の fold の平場で推定）

| 項 | 中身 |
|---|---|
| レーティング_相対 | μ − そのレースの出走馬の μ の平均 |
| レーティング_伸び | μ − 3走前のレース前の μ（3走未満は 0） |
| レーティング_不確かさ | σ − そのレースの出走馬の σ の平均（出走数が少ない・休み明けほど大きい） |

### 出すもの

- 係数（fold ごと）と θ × 標準偏差、平場の log-loss・AUC・キャリブレーション誤差（市場だけ / 市場＋レーティング / 3b / 3b＋レーティング）
- 参考：1着の予測の AUC（今のモデル・市場・レーティングだけ）
- 達成率は**今の本命の買い方（券種混合・金額の余裕×1.4・15点まで）**で（平場 5,000 レース）。対応のある比較：市場だけとの差、3b との差
- **試した案の数**：2（R、3b+R）。v8 のこのフェーズの合計は **60**

### 平場の全レースでの比較（`py -m src.v8 final-compare`）

- 市場だけ / 3b / 3c / 3b+3c / R / 3b+R を、今の本命の買い方で、平場の全レース（fold 2〜5、約4万2千）で。全体・fold ごと・対応のある比較（市場だけ・3b との差）
- 新しい案ではなく、これまでの案の見直しなので、試した案の数は増やさない。ただし 5,000 レースで選んだ案を同じデータの残りで見るので、
  差が小さいときは「選んだ分だけ良く見えている」可能性を割り引く
- `--no-rating` でレーティングの版を外す（4通り）。`--sample 10000` などで一部だけも可
- 時間の目安：1レースあたり 6通りで約 15〜30 ミリ秒 → **約 20〜40 分**（`--no-rating` で約 2/3）。途中で「残り約 N 分」を表示

| 順 | コマンド | 時間の目安 |
|---|---|---|
| 13 | `py -m src.v8 rating` | 初回 15〜30分（傾きの表を作り直すため。tilt・stakes も次回は作り直しになる）、2回目以降 5〜10分 |
| 14 | `py -m src.v8 final-compare` | 20〜40分（夜に） |
