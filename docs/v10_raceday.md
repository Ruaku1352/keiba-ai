# v10：当日の仕組み（毎週末の重賞で F の買い目を自動で作る。有馬記念のリハーサル）

> 開発記録。確認のテスト（v9）で F を採用した。毎週末の重賞すべてで、有馬記念と同じ仕組みを自動で動かし、
> お金は賭けない記録（練習）にする。今の毎週のコマンド（fetch / predict --sheet / results --sheet / train）は比較のため、そのまま残す。

## F（定義は変えない）

券種混合（3連単・3連複・馬単・馬連）× 市場（単勝オッズ）＋当日の傾向（3b）× 金額の余裕 ×1.4 × 15点まで × 12,000円。

- 当日の傾向：同じ日・同じ競馬場・同じ芝ダで、対象レースの発走の **40分以上前** に発走し、**その時点で結果が届いていた** レース
- 係数（β・θ）と γ・δ：レースの日より前の平場（2011年〜）で推定（`data\raceday\coefs\coefs_<日付>.json`）。12月中旬に `freeze` で固定
- 3連単などの確率は Henery 型。配当の推定は市場の確率と払戻率から（検証と同じ）

## 毎週の手順

| いつ | すること | 時間の目安 |
|---|---|---|
| 金曜の夜（土曜に重賞があれば） | いつもの `py -m src.jvlink fetch --option 1`（出馬表）→ `py -m src.v6 predict --date <その日> --sheet`（今の6頭BOX。そのまま）→ **`py -m src.raceday prep --date <土曜> --schedule`** | prep 10〜20分（データの読み込み 1〜2分 ＋ 係数の推定。固定した後は 2〜3分） |
| 土曜の夜（日曜に重賞があれば） | 同じく fetch → predict --sheet → **`py -m src.raceday prep --date <日曜> --schedule`** | 同じ |
| 日曜の夜（月曜開催なら） | 同じく **`prep --date <月曜> --schedule`** | 同じ |
| 当日 | **何もしなくてよい**。PC はつけたまま（スリープしない設定）。会場ではスマホでシート「当日の買い目」を見るだけ | — |
| 月曜 | いつもの fetch → `py -m src.v6 results --sheet`（今の6頭BOX。そのまま）→ **`py -m src.raceday score --sheet`** | score 1〜3分 |

- `prep` の `--date` を省略すると「明日」。`--schedule` でタスクスケジューラにも登録する（下）
- 出馬表の後に取消・乗り替わりがあっても、当日は速報の単勝オッズが無い馬（取消）を自動で除く

## 当日の自動実行（`py -m src.raceday update`）

タスクスケジューラが 9:00 から最後の重賞の発走まで **10分おき**、さらに **各重賞の発走60分前・20分前ちょうど** に実行する。1回の中身：

1. **時計の確認**：インターネットの時刻（HTTP の Date）と PC の時計を比べる。5分以上ずれていれば、シートの一番上とログに
   「!!!!! 時計の警告 !!!!!」を出し、発走までの時間はインターネットの時刻で判定する。タイムゾーンが日本でないときも警告。
   速報オッズの発表時刻が PC の時刻より5分以上未来のときも警告
2. **その日の結果**（JVRTOpen 0B12、開催日単位）を `data\raceday\<日付>\rt_results\` に追記。全馬の着順が確定した（データ区分 5〜7）レースを使う
3. **速報オッズ**（JVRTOpen 0B30＝全券種）を、まだ最終の買い目が無い重賞について取る（`data\jvlink\odds\rt\<日付>\` に保存。rt-odds と同じ場所）
4. **当日の傾向 → F の確率 → 券種混合の買い目**（レースごと）
   - 当日の結果が取れなかった（0B12 のエラー・変換の失敗）ときは **自動で「市場だけ」**（単勝オッズの確率そのまま）に切り替え、シートにそう出す
   - 結果は取れたが使えるレースがまだ無い（朝のうち）ときは F のまま（傾向の項は 0）
5. **本物のオッズで確かめる**：選んだ買い目を 0B30 のオッズで見て、`オッズ × 金額 < 50,000円` の買い目に「届かない → ○円で届く（+○円）」。
   全部届かせたときの合計（予算を超えるか）も
6. **保存**（`data\raceday\<日付>\<レースID>\`）
   - `latest.json`：毎回
   - `provisional.json`：発走60分前以降の最初の回（**仮の買い目**）
   - `final.json`：発走20分前以降の最初の回（**最終の買い目**）。これ以降、そのレースは取り込みも更新もしない
   - 失敗したとき（オッズが取れない・計算できない）は何も上書きしない。前の晩の準備と前回の買い目がそのまま残る
7. **シート「当日の買い目」**（タブが無ければ作る）に書く。書けなくても保存した買い目は残る
8. **ログ**：`data\raceday\<日付>\log.csv`（実行ごと・レースごと：時刻・時計のずれ・段階・結果とオッズの取得の秒数・オッズの発表時刻・
   使ったレース・処理時間・警告）、`result_times.csv`（各レースの結果を初めて取れた時刻と、発走からの分）、`run.log`（画面の出力）

## タスクスケジューラ（`py -m src.raceday schedule --date 20261101`、削除は `--remove`）

- `prep --schedule` でも登録される。タスク名は `keiba_raceday_<日付>`。定義は `data\raceday\<日付>\task.xml`
- **管理者権限は要らない**（自分のユーザーで「ログオンしているときだけ」動く設定）。「アクセスが拒否されました」と出たら、
  PowerShell を「管理者として実行」して同じコマンドを
- 確認：`schtasks /query /tn keiba_raceday_20261101`、手で1回動かす：`schtasks /run /tn keiba_raceday_20261101`
- 窓が出ないように pythonw.exe で動かす（出力は `data\raceday\<日付>\run.log`）
- PC の設定（最初に1回）：電源とスリープ →「スリープしない」、Windows Update のアクティブ時間に 9〜17時を入れる、
  日付と時刻 →「時刻を自動的に設定する」オン・タイムゾーン (UTC+09:00)。デュアルブートで9時間ずれる件は、Linux 側で
  `timedatectl set-local-rtc 1` にするか、Windows 側で RealTimeIsUniversal を設定すると直る（どちらか一方）

## 答え合わせ（`py -m src.raceday score [--sheet]`、月曜の fetch のあと）

- 保存した最終の買い目（`final.json`）を、確定した払戻（HR）で照合する。券種ごとに、当たった組の 100円あたりの払戻 × 金額 / 100
- **返還**：出走取消・発走除外・競走除外（異常区分 1〜3）の馬を含む買い目は返還（払戻ではなく「返還」として別に数え、熱い当たりの判定には入れない）
- 通算：レース数・熱い当たり・達成率（Wilson 区間）・的中・投資・払戻・返還・回収率・予測の達成確率（平均）。
  **今の6頭BOX**（predict --sheet の最終の予測）を同じレースで並べる
- 保存：`data\raceday\score_races.csv`・`score_summary.csv`。`--sheet` でシート「当日の答え合わせ」にも

## 練習（ドライラン：`py -m src.raceday replay --date 20261025`）

平日に、過去のレース日の流れを再現する（本番の保存先とは別の `data\raceday\replay\` に書く）。

- 出走馬：その日の確定データ（結果の列は使わない）。係数：その日より前のデータで推定
- 当日の結果：確定データのうち、発走から20分たったレースは届いたとみなす
- オッズ：その時刻までに保存した速報（`rt-odds` で取ったもの）があればそれ、無ければ確定オッズで代用（シートとログにそう出る）
- 朝9時から10分おき＋発走60分前・20分前の回を順に動かし、最後に答え合わせ（確定データ）まで出す。`--at 1520` でその時刻の1回だけ、
  `--sheet` でシート「当日の買い目（再現）」にも書く

| 順 | コマンド | 期待される出力 | 時間の目安 |
|---|---|---|---|
| 1 | `py -m src.raceday replay --date 20261025` | 重賞ごとに、時刻・段階（途中/仮/最終）・点数・金額・予測・使ったレースの一覧 → 最終の買い目 → 答え合わせの表 | 10〜20分（データの読み込み・係数の推定。同じ日をもう一度なら係数は保存を使う） |

## 係数の固定（12月中旬）

`py -m src.raceday freeze`（最新の `coefs_*.json` を `frozen_coefs.json` に）。以後の prep はこの係数を使う（prep の出力に「・固定」）。
やめるときは `unfreeze`。

## v10b の修正（10/31）：当日の結果（0B12）の変換で落ちていた件

- 症状：log.csv の「結果」に `結果の変換に失敗: KeyError: '_seq'`。当日の傾向が使えず「市場だけ」になっていた
- 原因：`fetch_rt_results` が書く CSV には、ふだんの fetch の CSV にある `_seq`（取得した順）の列が無いのに、変換（`jvmap.dedupe_records`）が `_seq` を読んでいた。
  テストの偽物の取り込みが本物の CSV の形と違っていたため、見つからなかった
- 直したこと：読むときに `_seq` が無ければファイルの行の順で振る（`raceday.load_rt_results`）。書き出しは変えない（すでに書いた CSV にそのまま追記できるように）。
  prep.json の形・タスクの登録内容・保存先は変えていない
- テスト：偽の JV-Link から本物の `fetch_rt_results` で CSV に書き（`_seq` なし・同じ日に3回追記・速報 3/4/5 の版が混ざる）、
  `LiveSource.fetch_results` → `day_results_from_raw` → `compute_plan`（当日の傾向あり）まで。着順が確定したレースだけが1回ずつ使われ、
  速報の途中（4 まで）のレースは使われないことを確かめる。修正前のコードではこのテストが同じ `KeyError: '_seq'` で落ちることも確認
- run.log に毎回「当日の結果: 0B12: ○ レコード（取得 ○秒）」とエラー・変換の失敗、レースごとの「当日の傾向に使ったレース」を出す
- 確認のコマンド：`py -m src.raceday check-results --date 20261031`（買い目は作らない。レースごとの最新の版・着順の確定・1〜3着と、
  対象の重賞の当日の傾向に使えるレース）

## v10c の修正（10/31）：シートの組番が日付に化けていた件

- 症状：シート「当日の買い目」で 馬連 6-8 →「2026-6-8」、3連複 2-8-10 →「2002-8-10」など
- 原因：シートへの書き込みは USER_ENTERED（金額・確率を数値として表示するため）で、6-8 のような文字が日付と解釈された
- 直したこと：組番のセル（「仮の買い目」の行・ヘッダーの日付・答え合わせの着順も）は先頭に ' を付けて文字として書く（' はシートには表示されない）。
  金額・確率などほかの数値の列は今までどおり
- 組番の形をスマッピー・即PAT と同じにした：馬連・3連複は小さい順に「-」（6-8、2-8-10）、馬単・3連単は着順の順に「→」（10→11、3→8→2）。
  前に保存した買い目（"3-8-2" の形）も、保存してある馬番から作り直して表示する
- 保存した買い目からシートだけを書き直すコマンド：`py -m src.raceday sheet --date 20261031`（ドライランの分は `--replay`）。買い目は作り直さない
